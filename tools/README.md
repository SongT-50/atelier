# 경계 검사 (`boundary_check.py`)

이 저장소는 공개된다. 나가면 안 되는 것이 섞였는지 커밋 전에 본다.

```bash
python tools/boundary_check.py              # 이 저장소
python tools/boundary_check.py <경로>...    # 반입 후보를 미리
python tools/boundary_check.py --mutate     # 대조군에 이빨이 있는지
python tools/fp_measure.py <경로>...        # 적발을 판정해서 오탐률을 낸다
python tools/boundary_check.py --history    # 지웠던 것까지 — 히스토리 전체
```

⚠️ **모르는 옵션은 거부한다**(종료 코드 `2`). 전에는 오타 난 플래그를 **경로로 읽고**
대상 0개로 「✓ 위반 0건」을 찍었다. 실제로 그렇게 한 번 나왔다(2026-08-21).
### 「0건」이 「아무것도 안 봤음」인 경우가 바로 그것이다.

종료 코드 — `0` 깨끗함 · `1` 위반 발견 · **`2` 검사기 고장(대조군 실패)**.
`2` 일 때의 「0건」은 **근거가 아니다.**

## 커밋 때 자동으로 돌리기

```bash
git config core.hooksPath tools/hooks
```

`pre-commit` 은 **인덱스**(워킹트리 아님 — add 뒤에 또 고쳤을 수 있다)를,
`commit-msg` 는 **커밋 메시지**를 본다. 메시지는 pre-commit 시점에 아직 없어서 따로 건다.

### 이 훅이 막지 못하는 것

- **복제해도 자동으로 안 켜진다.** git 은 훅 경로를 복제하지 않는다. 위 한 줄을 **각자** 쳐야 한다.
- **`git commit --no-verify` 로 우회된다.** 훅은 실수를 막지 고의를 막지 못한다.
- **`python` 이 없으면 커밋을 막는다**(통과시키지 않는다). 검사를 못 돌린 것은 「깨끗함」이 아니다.

⇒ 그래서 밖으로 내보내기 **직전에는 인자 없이 한 번 더** 돌린다. 그때는 추적 파일 전체와
커밋 메시지 전체를 본다.

### 발행 직전 — `pre-push`

바로 위 문장이 문제다. **「한 번 더 돌린다」가 사람의 기억에 걸려 있다.**

> **소스 사건** — 이 저장소를 발행하면서, 돌리기로 되어 있던 검사를 **푸시하고 나서** 돌린 일이
> **하루에 두 번** 있었다(2026-08-18). 두 번 다 결과는 깨끗했다.
> ### 그건 운이지 절차가 아니다. **사람이 기억해야 도는 절차는 절차가 아니다.**

`tools/hooks/pre-push` 는 push 전에 **둘**을 돌린다.

1. ### 이 저장소의 경계 검사를 **`--history` 로.** 워킹트리만 보는 것은 검사가 아니다.
2. **로컬에 발행 게이트가 설정돼 있으면** 그것도. 게이트가 막으면 push 를 막는다.

```bash
git config publish.gate /경로/검사기   # 걸기
git config --unset publish.gate        # 풀기
```

- **설정 안 했으면 조용히 통과한다.** 남의 복제본까지 막을 이유가 없다.
- **설정해 뒀는데 그 파일이 없으면 막는다.** 검사를 못 돌린 것은 「깨끗함」이 아니다.
- **경로를 훅 파일에 적지 않는다** — 이 파일은 커밋돼 공개된다.
  로컬 설정(`.git/config`)은 커밋되지 않는다.
- ⚠️ `core.hooksPath` 를 쓰면 `.git/hooks/` 는 **무시된다.** 훅은 그쪽 디렉토리에 넣어야 한다.

| 칸 | 내용 |
|---|---|
| **소스 사건** | 위 인용. 검사 순서를 사람이 기억하다가 두 번 놓쳤다. |
| **적용** | 이 저장소에서 나가는 모든 `git push`. |
| **비적용** | 게이트를 설정하지 않은 복제본 — 통과시킨다. |
| **비용** | push 가 게이트 실행만큼 느려진다. 그리고 **게이트가 「경고」로 내린 것을 매번 읽어야 한다.** |
| **반증자** | **관측 창 = 다음 20회 push.** 그 사이 이 훅이 막은 진짜 위반이 `0` 이고 **사람이 잡은 위반도 `0`** 이면 막을 것이 애초에 없었던 것이다 — 그때는 훅을 늘리지 말고 **게이트의 대조군부터 의심한다.** 반대로 **훅을 우회하는 습관(`--no-verify`)이 생기면** 그건 비용이 아니라 **반증**이다. 그 순간 이 게이트는 이루려던 것을 못 이룬다. |

**못 막는 것** — `--no-verify` 로 우회된다. 그리고 이 훅은 **무엇을 볼지 정하지 않는다.**
그건 걸어 둔 게이트가 정한다. 게이트가 히스토리를 안 보면 히스토리는 **안 본 것**이다.

### 반증자

**관측 창** = 다음 20커밋. **분모** = 그 사이 커밋된 파일 수(매 실행 출력에 찍힌다).

이 규칙이 **틀렸거나 쓸모없다**고 판정할 관측:

- **(a) 아무것도 안 막고 있다** — 20커밋 동안 이 검사가 잡은 진짜 위반이 `0` 이고,
  **같은 기간 사람 검토가 잡은 위반도 `0`** 이면, 이 저장소에는 애초에 샐 것이 없는 것이다.
  그때는 검사를 늘리지 말고 **대조군부터 의심한다.**
- **(b) 「0건」이 근거가 못 된다** — 검사는 조용한데 **사람이 계속 위반을 잡아내면**,
  패턴이 실제 새는 길을 못 덮고 있는 것이다. 이 경우 검사의 통과는
  *"깨끗하다"* 가 아니라 *"이 14종에 안 걸렸다"* 로만 읽어야 한다.
  ### 이미 (b)가 한 번 관측됐다 — 아래를 볼 것.

**정지 조건**: (a)가 관측되면 이 검사를 지운다. (b)가 두 번 관측되면
패턴을 늘리는 대신 **반입 절차 자체를 바꾼다**(자동 검사를 통과 조건에서 내리고 사람 검토를 조건으로 올린다).

⚠️ **「틀렸다」와 「비싸다」를 섞지 않는다.** *"매번 돌리기 귀찮다"* 는 **비용**이지 반증이 아니다.
판별 = *"그 부담이 「나가면 안 되는 것을 막는다」를 무너뜨리나?"* — 귀찮아서 **안 돌리게 되면** 그건 무너뜨린 것이고,
돌리면서 투덜대는 것은 비용이다.

## 대조군 — 왜 본 검사보다 먼저 도나

밖을 재는 일은 산출 대부분이 `0건` 이다. 그 `0` 이 **진짜 부재**인지 **계측기가 죽은 것**인지
못 가르면 이 검사로 얻은 값은 전부 무의미하다. 그래서:

- **양성** — 반드시 잡혀야 하는 표본. **패턴 전 종류를 하나씩 덮는다**(아래 변이 시험으로 확인).
  하나라도 놓치면 **본 검사를 안 돌리고** 종료 코드 `2`.
- **음성** — 걸리면 안 되는 표본. 없으면 **과잉 검사를 못 본다.**
  실제 대상에서 나온 오탐은 **전부 여기 들어온다.**

> **개수는 문서에 안 적는다 — 실행 출력에 찍힌다.**
> 적어 뒀더니 대조군을 늘린 뒤 이 파일과 최상위 README 두 곳이 실제 값과 어긋나 있었다(2026-08-18 발견).
> 숫자를 두 곳에 두면 한 곳은 반드시 늙는다.

### 대조군에 **이빨이 있나** — 변이 시험

```bash
python tools/boundary_check.py --mutate
```

패턴을 **하나씩 제거**하고 대조군이 그것을 잡는지 본다.
대조군이 **있다**는 것과 대조군에 **이빨이 있다**는 것은 다른 문장이다 —
양성 표본이 어떤 패턴을 안 덮고 있으면 그 패턴은 죽어도 아무도 모르고,
그 패턴에 대해서는 **대조군이 없는 것과 같다.**

**2026-08-18 실측: 분모 14 · 죽여도 조용한 패턴 0종.** ⚠️ 이 「0」을 그대로 읽으면 안 된다 — 아래.

**언제 돌리나** — 패턴이나 대조군을 **고칠 때마다.** 훅에는 **안 걸었다**:
매 커밋마다 같은 답이 나오는 절차는 절차가 아니라 형식이고, 패턴이 안 바뀌면
결과도 안 바뀌기 때문이다. 바뀔 때만 돌린다.

> ⚠️ 통째 제거는 **거친 변이**다. 실제 고장은 그렇게 오지 않는다.
> 그래서 미묘한 변이도 함께 돌린다 — 아래.

### 미묘한 변이 — 거친 시험이 「100%」라고 할 때 (2026-08-22)

자릿수 하한을 한 칸 밀고 · 앞뒤 조건을 하나 빼고 · 문자 종류를 넓히고 · 갈래를 하나 뺀다.
그리고 **대조군이 알아채는지** 본다.

| 시험 | 결과 |
|---|---|
| 통째 제거(거친) | **14/14 전부 잡힘** ← 여기까지만 보면 완벽하다 |
| ### 미묘한 약화 | ### 변이 92개 중 **잡힘 29 · 등가 52 · 사각지대 11** |

**「사각지대」 = 실제로 달라지는데 대조군이 조용한 자리.** 그 패턴은 **약해져도 아무도 모른다.**

#### 왜 「등가」를 따로 세나

대조군이 조용한 변이가 처음엔 **63건**이었다. 그런데 그중 대부분은
**어떤 글에서도 원본과 다르게 굴지 않는 변이**였다 — 대조군을 아무리 늘려도 못 잡는다.
### 둘을 섞어 「사각지대 63건」이라 적으면 그건 또 **낱말을 센 것**이다.

⇒ 그래서 실제 글에 둘 다 돌려 **달라지는지 먼저 본다.**

#### ### ⚠️ 그리고 「등가」는 **글이 좁으면 부풀려진다**

| 무엇으로 쟀나 | 등가 | 사각지대 |
|---|---:|---:|
| 이 저장소의 글만 | 58 | **5** |
| **+ 밖의 저장소 5곳** | 52 | ### **11** |

### 같은 도구·같은 변이인데 사각지대가 **두 배**가 됐다.
좁은 글에서 *"안 달라졌다"* 는 **안 달라진 것이 아니라 달라질 글이 없었던 것**이다.

```bash
python tools/boundary_check.py --mutate                 # 이 저장소 글로만 (과소평가된다)
python tools/boundary_check.py --mutate <경로>...        # 밖의 글을 더해서
```

#### 이 수는 **실패가 아니라 측정값**이다

종료 코드를 올리지 않는다. `0` 이 되어야 하는 값도 아니다 —
대조군을 늘려 줄이는 것이 맞고, 실제로 **경계값 표본 11개를 넣어 74→63으로 줄였다**
(그 뒤 등가를 갈라내서 11이 됐다).

### ⚠️ 자작 표본만으로는 아무것도 증명되지 않는다

양성 표본은 우리가 만든 문자열이다. 그것만 통과하는 것은 **동어반복**이다.
그래서 둘 다 실측했다 (2026-08-14):

| 무엇에 돌렸나 | 결과 | 무엇을 보였나 |
|---|---|---|
| **정제 안 된 실제 대상** (산출 원본 234파일) | **123건** 적발 | 검사가 **실제로 잡는다** |
| **정제된 대상** (이 저장소 추적 파일) | **0건** | 정상 대상에 **조용하다** |

### 이미 공개된 저장소 27곳에 돌려서 무엇이 나왔나 (2026-08-14)

만들어 두고 **정작 이미 밖에 나가 있는 것들에는 안 돌려봤다는 것**을 깨닫고 돌렸다.
커밋 메시지 전수(1,554줄) + 커밋 작성자.

- **진짜 위반 1건** — 어느 저장소의 커밋 메시지에 개인 이메일. **이미 공개돼 있어 되돌릴 수 없다.**
- ### **검사기 자신의 구멍 1개** — **커밋 작성자(author/committer) 필드를 안 보고 있었다.**
  본문도 메시지도 아닌 **메타데이터**로 새는 길이고, `git log` 로 누구나 읽는다.
  이 구멍으로 **이 저장소를 발행할 때 개인 이메일이 함께 나갔다.**
  구멍을 메우자마자 자기 저장소에서 걸렸다.
- **오탐 3종** — `.env.local`·`settings.local.json`(파일명을 내부 호스트로 읽음),
  `12345+name@users.noreply.github.com`(git 작성자 표준 형태). 전부 음성 대조군에 넣었다.

⇒ 「밖을 재는 도구」를 만들고 **밖에 이미 나가 있는 우리 것에 안 돌려본 것**이 가장 큰 구멍이었다.

#### 고쳤지만 **완전히 지워지지는 않았다**

이 저장소의 커밋 11개를 다시 써서 작성자를 noreply 로 바꾸고 force push 했다.
현재 화면은 깨끗하다. **그런데 옛 커밋은 SHA 로 조회하면 아직 나온다.**

```
현재 HEAD          → noreply                  ✅
옛 SHA 로 직접 조회 → 개인 이메일이 그대로     ⚠️
```

**force push 는 지우는 게 아니라 가리는 것이다.** 호스팅 쪽은 닿지 않게 된 객체를
한동안 그대로 보관한다. 완전히 없애려면 저장소를 지우고 다시 만들거나 호스팅 쪽에 요청해야 한다.

여기서는 **가린 상태로 두기로 했다** — SHA 를 아는 사람이 없고(클론 0) 검색·링크로도 닿지 않는다.
그래서 *"지웠다"* 가 아니라 ### **"가렸고, 완전 제거는 아니다"** 라고 적는다.
이것을 *"처리 완료"* 로 적으면 그 순간 이 파일이 거짓말이 된다.

### ### 「지웠다」는 착각 — 가장 값진 발견

이미 공개된 저장소들의 **히스토리 전체**(지금 파일이 아니라 지웠던 것까지)를 훑었더니,
**최신 파일은 깨끗한데 과거 커밋에는 남아 있는** 경우가 여럿 나왔다. 그중 하나는
**개인 연락처 수백 건**이었다. 커밋에서 지웠고, 배포된 사이트에서도 안 보이고,
그래서 **처리됐다고 믿고 있던 것**이다.

```
현재 파일          → 없음        ✅  ← 여기까지만 보면 깨끗하다
배포 사이트        → 404        ✅
그러나 git 히스토리 → 그대로     ⚠️  ← clone 한 번이면 누구나 꺼낸다
```

⇒ ### **git 에서 「지운다」는 것은 최신 상태에서 빼는 것이지 없애는 것이 아니다.**
⇒ 그래서 **워킹트리만 검사하는 것은 검사가 아니다.** 반드시 히스토리 전체를 봐야 한다.

```bash
# 워킹트리만 (부족하다)
python tools/boundary_check.py

# 히스토리 전체 — 지웠던 것까지
python tools/boundary_check.py --history
```

### `--history` 는 무엇을 어떻게 보나 (2026-08-21 신설)

**모든 blob 을 sha 로 묶어 한 번씩만** 본다. 같은 내용은 sha 가 같기 때문이다.
`git log -p` 로 훑으면 같은 내용이 커밋 수만큼 반복돼 큰 저장소에서 안 끝난다.
파일 내용뿐 아니라 **지금은 없어진 경로 문자열**과 **커밋 메시지·작성자 전체**도 함께 본다.

**이 모드가 살아 있는지 실측했다.** 버리는 복제본에 AWS 키 모양을 커밋하고 **다시 지운 뒤**:

| 무엇으로 봤나 | 결과 |
|---|---|
| 워킹트리 (기본) | **위반 0건 · 종료 코드 0** ← 여기까지만 보면 깨끗하다 |
| ### `--history` | ### **위반 1건 · 종료 코드 1** — 지운 커밋 안에서 찾았다 |

⇒ 이 표의 윗줄이 **우리가 남의 저장소에서 실제로 본 상태**였다. 아랫줄이 없으면 못 본다.

**속도** — 제3자 저장소 둘에서 blob 508개 **6.1초**, 659개 **11.0초**.
⚠️ 다만 둘 다 **얕은 복제**(최근 50~61커밋)라 **전체 히스토리의 blob 수가 아니다.**
큰 저장소에서 얼마나 걸리는지는 **안 쟀다.**

### 이 검사기가 **대용량에서 멈춘다**

**절반은 고쳤다** — `--history` 가 `git rev-list --objects --all` 로 **blob 을 한 번씩만**
훑는다(위 절). 같은 내용을 커밋 수만큼 다시 읽던 문제는 없어졌다.

**남은 절반** — 한 줄씩 패턴 전 종류를 도는 구조는 그대로다. blob 하나에 대략 10~17ms 였으니
blob 이 수만 개면 여전히 분 단위다. **큰 저장소에서 실제로 재보지 않았다** — 그러니
*"이제 큰 저장소도 된다"* 고 쓰지 않는다. 2MB 초과·바이너리 blob 은 **안 읽고 따로 찍는다.**

### 음성 대조군이 실제로 과잉 검사를 잡았다

첫 판은 같은 실제 대상에서 **9,695건**을 냈다. 그중 **9,572건이 오탐**이었다 —
`kr-phone` 이 `010`·`019` 로 시작하는 11자리 물량·가격 숫자열을 번호로 읽고 있었다.
우리가 처음 넣은 음성 표본에는 **긴 숫자열이 없어서** 이걸 못 봤다.
실제 대상에 돌리고 나서야 드러났고, 그 오탐 문자열들을 음성 대조군에 **그대로 넣었다**.

⇒ 9,695 → **123건**. 남은 123건은 전부 진짜 절대경로·사용자명이다.

> ### ⚠️ 이 「9,572건 제거」는 **독립적인 측정이 아니다.**
> 오탐을 **그 대상에서** 발견하고 → 그 유형을 대조군에 넣고 → **같은 대상에** 다시 돌려서 잰 값이다.
> 조정한 데이터로 조정의 성과를 잰 것이므로, 이 수치는 *"그 대상에서 오탐이 줄었다"* 까지만 말한다.
> **「이 검사기의 오탐률이 낮다」의 근거로는 쓸 수 없다.**
> 규칙이 경고한 그대로다 — *"샘플이 검사를 설계할 때 본 그 데이터에서 나왔으면
> 통과는 아무것도 증명하지 않는다."* 오탐을 실제 대상에서 찾은 것까지는 맞았고,
> **그 뒤 같은 데이터로 성과를 인용한 것**이 틀렸다.
>
> 제대로 재려면 **한 번도 안 본 저장소**에 돌려서 오탐률을 세야 한다.
> ### ⇒ 2026-08-18 에 했다. 바로 아래.

## 한 번도 안 본 저장소 5곳에 돌렸다 (2026-08-18)

바로 위 문단이 *"아직 안 했다"* 고 적어 둔 그 측정이다. **우리가 만들지 않았고 설계할 때
본 적도 없는** 제3자 공개 저장소를 골라 돌렸다.

**대상** — `psf/requests` · `jqlang/jq` · `konlpy/konlpy` · `docker/awesome-compose` ·
`public-apis/public-apis`. 언어·성격이 겹치지 않게 골랐다(파이썬 라이브러리 · C · 한국어 NLP ·

**분모** — 파일 **1,189개** · 줄 **267,549**.

**재현** — 판정을 손으로 세면 재현이 안 되므로 코드로 고정했다.

```bash
git clone --depth 50 <저장소> ...
python tools/fp_measure.py <복제한 경로>...
```

⚠️ 이 스크립트는 **현재** 패턴으로 잰다. 아래 3.7% 는 좁히기 **전** 값이라,
그대로 재현하려면 그 직전 커밋의 검사기로 돌려야 한다.

### 결과 (고치기 **전** — 처음 보는 데이터에서 잰 값)

| | 건수 | 비율 |
|---|---:|---:|
| 적발 합계 | **912** | |
| **오탐** (그 패턴이 잡겠다고 선언한 대상이 아님) | **34** | **3.7%** |
| 진양성 | 878 | 96.3% |

오탐 34건의 정체 — URL 경로를 홈 디렉토리로 읽음 12 · URL 의 `user:pass@host` 를 이메일로 읽음 14 ·
SSH 원격 주소 `git@host:` 를 이메일로 읽음 2 · `password = 함수호출(...)` 을 비밀 대입으로 읽음 3 ·
옥텟이 255를 넘는 것을 사설 IP 로 읽음 1 · 파이썬 모듈의 `.local` 속성 접근을 내부 호스트로 읽음 2.

### ⚠️ 「오탐률」과 「위반 적중률」은 **다른 값이다**

진양성 878건 중 **실제로 개인정보·머신정보인 것은 607건**이고, 나머지 **271건은 패턴은
맞았지만 그 저장소가 일부러 공개한 것**이다 — 문서·테스트용 예시 사설 IP 235, 자리표시자
이메일 25, 컨테이너 내부 경로 6, 테스트 픽스처 인증서 4, 설정상 가짜 호스트 1.

⇒ 반입 선별기로 쓰면 **적발 3건 중 1건은 「패턴은 맞았는데 문제는 없는 것」**이다.
*"오탐 3.7%"* 만 인용하면 이 부담이 안 보인다. **둘을 같이 적는다.**

### 고쳤다 — 그리고 **그 뒤 수치는 인용하지 않는다**

오탐 5종을 음성 대조군에 넣고, 그러기 위해 패턴을 좁혔다(URL 문맥 거부 · 옥텟 0–255 ·
비밀 대입에서 함수 호출 제외). 같은 5곳에 다시 돌린 결과:

```
적발 912 → 880    오탐 34 → 2 (0.2%)    진양성 878 → 878  ← 하나도 안 잃었다
```

**진양성이 그대로인 것**은 확인해 둘 값이다. 좁히면서 진짜를 같이 버렸으면 오탐률만 예뻐진다.

> ### ⚠️ 그러나 이 **0.2% 는 독립적인 측정이 아니다.**
> 오탐을 이 5곳에서 발견하고 → 그 유형을 대조군에 넣고 → **같은 5곳에** 다시 잰 값이다.
> 바로 위에서 9,572건 때 저질렀다고 적어 둔 **그 실수와 구조가 같다.**
> 그래서 인용해도 되는 값은 **3.7%(고치기 전, 처음 보는 데이터)** 쪽이고,
> `0.2%` 는 *"이 5곳에서 그 5종이 사라졌다"* 까지만 말한다.
> **다음 오탐률 측정은 또 다른, 한 번도 안 본 저장소여야 한다.**

### 이 측정이 **안 잰** 것

- **위음성(놓친 것)** — **안 쟀다.** 정답지가 없다. 이 저장소들에 우리가 못 잡은 비밀이
  몇 건 있는지 모른다. *"오탐이 적다"* 는 *"잘 잡는다"* 가 아니다.
- **히스토리** — 워킹트리만 봤다. 위 「지웠다는 착각」절이 말하는 바로 그 구멍을
  이번 측정은 **안 봤다.**
- **`--depth 50`** — 얕은 복제라 그 이전 커밋은 대상에 없었다.
- **판정자** — 오탐/진양성 판정 규칙을 **이 데이터를 보고** 만들었고, 돌린 쪽과 판정한 쪽이
  같다. 생성자와 검증자가 안 나뉘었다. 판정 규칙은 코드로 고정해 두어 재현은 되지만,
  **규칙 자체가 관대했는지는 남이 봐야 안다.**

### 고치지 **않은** 오탐 1종

파이썬 표준 모듈의 `.local` 속성 접근을 내부 호스트명으로 읽는다(2건). **고치지 않기로 했다** —
구조상 `모듈.local` 속성 접근과 진짜 `호스트.local` 은 같은 모양이라, 일반화해서 빼면
**진짜 `.local` 내부 호스트명을 통째로 놓친다.** 이름 목록을 만드는 방법은 그 목록에
없는 것을 영원히 못 보게 한다. 그래서 **오탐 2건을 남기고 잡는 쪽을 택했다.**
이건 해결이 아니라 **선택**이고, 그렇게 적는다.

## ### 적발 수를 「위험 N건」으로 읽는 것 — 만든 쪽이 저지른 오용 (2026-08-21)

이 도구를 만든 쪽이 이 도구로 어떤 저장소들을 훑고 **「위험 수천 건」이라고 보고했다.**
확인해 보니 **대부분이 아무것도 아니었다.**

| 무엇이 잡혔나 | 실제 | 판정 |
|---|---|---|
| 업계 용어 수백 건 | **공개 데이터 포털 API 의 데이터셋 이름**이었다 | 이미 공개된 것 |
| 같은 용어 116건 | **법령 조문 인용**이었다 | 공개 법령 텍스트 |
| 조직 이름 수십만 건 | 당사자가 **스스로 내건 공개 이름**이었다 | 공개는 그쪽 선택 |

### 무엇을 틀렸나

**패턴은 맞았다.** 그 문자열들은 정말 그 패턴이 잡겠다고 선언한 것이었다.
### 틀린 것은 **그 다음 한 걸음을 안 밟은 것**이다 —

> ① 이 문자열이 그 패턴이 **잡겠다고 선언한 것**이 맞나
> ② 그것이 **실제로 나가면 안 되는 것**인가

②를 가르는 것은 **낱말이 아니라 출처와 소유**다.

- **출처** — 이미 공개된 데서 왔으면(공개 API · 법령 · 표준 용어) 그건 **누출이 아니다.**
  실제로 판정을 뒤집은 것은 데이터 안의 **출처 필드 한 줄**이었다. 낱말을 아무리 세도 안 나왔다.
- **소유** — ### **내 것이면 공개는 선택이다. 남의 것이면 선택이 아니다.**
  같은 데이터라도 *"내 조직 이름"* 과 *"거래 상대의 식별 가능한 금액"* 은 다른 문제다.

### ⚠️ 가장 아픈 부분

### **이 구분은 이미 `fp_measure.py` 에 적혀 있었다.**
그 파일은 첫머리에 *"두 가지를 따로 센다 — (A) 패턴 오탐 (B) 위반 여부. 섞으면 둘 다 못 읽는다"*
라고 적고 있다. **적어두고, 정작 쓸 때 안 썼다.**

⇒ 그래서 **적는 자리를 옮겼다.** 문서가 아니라 **출력**에 붙인다 —
위반이 나오면 검사기가 매번 위 두 질문을 함께 찍는다(`CITE_WARNING`).
### 규칙은 읽을 때가 아니라 **쓸 때** 작동해야 한다.

## 그리고 같은 날, 반대쪽 실수도 했다

같은 저장소를 **읽기 한도만 올려서** 다시 돌렸더니 적발이 **492 → 3,080 (6.3배)** 이 됐다.
처음 수는 blob 의 **22% 만 보고** 나온 것이었다.

⇒ 두 실수는 **한 쌍**이다.
### **안 본 것을 「깨끗함」으로 읽었고, 본 것을 「위험」으로 읽었다.**
분모를 안 적으면 앞이 나고, 판정을 안 하면 뒤가 난다.

## 이 검사가 **못 잡는** 것

*"검사가 조용함"* 과 *"파일이 깨끗함"* 은 다른 문장이다. 아래는 **안 본 것**이지 없는 것이 아니다.

- ### 내부 식별자 — 패턴이 **없다.**
  티켓 번호 · 내부 규칙 번호 · 내부 태스크 ID · 내부 프로세스 약칭.
  **2026-08-14 반입 검토에서 실제로 나왔고, 자동 검사는 통과했으며, 사람이 읽어서 잡았다**
  (위 반증자 **(b)** 의 첫 관측). 일반화하면 오탐이 너무 커서 패턴화하지 않았다.
  ⇒ **반입 시 사람이 파일을 끝까지 읽는다.** 이건 선택이 아니다.
- **내부 저장소·디렉토리 이름** — 마찬가지로 패턴 없음.
- **구분자 없는 전화번호** — 같은 줄에 문맥 단어(연락·담당자·phone…)가 없으면 못 잡는다.
  오탐 9,572건을 없애려고 일부러 붙인 조건이고, **그 대가로 생긴 구멍이다.**
- **하이픈 없는 주민번호** — `\d{6}-[1-4]\d{6}` 만 본다.
- **2MB 초과 파일 · 바이너리** — 안 읽는다. 실행할 때마다 *"안 봤음"* 으로 따로 찍는다.
- **사용자명이 3자 미만인 머신** — 오탐이 커서 신원 패턴에서 뺀다.
- **URL 안쪽** — `scheme://호스트/home/...` 의 경로와 `scheme://user:pass@host` 의 userinfo 는
  **일부러 뺀다**(2026-08-18). 대가로 못 잡게 된 것: 호스트가 붙은 URL 경로에 진짜 사용자명이
  들어간 경우. 다만 `file:///home/사용자명` 은 호스트가 비어 있어 **그대로 잡히고**,
  질의 문자열 속 이메일(`?email=…`)도 **그대로 잡힌다** — 둘 다 양성 대조군이 지킨다.
- **순수 소문자 16자 이상 비밀** — `password = 무언가(...)` 처럼 뒤에 여는 괄호가 오면
  비밀이 아니라 호출로 보고 넘긴다. 괄호가 붙는 진짜 비밀은 못 잡는다.
- **`모듈.local` 형태의 내부 호스트** — 위 「고치지 않은 오탐」참고. 잡되 오탐 2건을 감수한다.
- **`noreply@` · `no-reply@` 주소** — 면제한다. 개인 연락처가 아니고, git trailer 로
  매 커밋에 붙어서 표현을 바꿀 수 없다. (앞의 「자기 문서를 잡은 이야기」와 처리가 다른 이유:
  그쪽은 **문서를 고쳐서** 해결됐지만 이쪽은 고칠 수 있는 표현이 아니다.
  그리고 이 면제는 검사를 **약화**하는 게 아니라 *"개인 식별 정보"* 라는 대상을 정확히 좁힌다.
  실제 이메일은 그대로 잡힌다 — 양성 대조군에 남아 있다.)

## 사용자명을 소스에 안 적는 이유

이 머신의 사용자명·홈 디렉토리명은 **런타임에 환경에서 읽는다**(`runtime_identity()`).
소스에 하드코딩하면 **검사기 자신이 경계를 위반한다.**
같은 이유로 대조군 표본도 파일에 완성된 형태로 두지 않고 조각으로 조립한다 —
그래야 검사기를 검사 대상에서 빼는 예외를 만들지 않아도 된다.
(예외를 만들면 그 파일에 진짜 비밀이 들어가도 영원히 못 잡는다.)
